# Release 2.27.1

在 2.27.0（资金安全/高并发稳定性/输入安全）基础上，本版聚焦**纯 Java 高频热路径的性能优化**，并修复一个潜伏的缓存边界缺陷。**无破坏性变更，可从 2.27.0 直接平滑升级。**

> 🟢 **向后兼容**：未改任何 API、数据结构或跨服同步协议。2.27.0 的服务器可无缝升级。

---

## ⚡ 性能优化（行为等价，资金安全路径未改）

以 [benchmark/](../../benchmark/) 模块在同一 JVM、相同输入下量化，行为等价自检 ALL PASS：

- **余额展示加结果缓存**（`DataFormat.shown` / `PEshownf`）：PlaceholderAPI、记分板、Tab、`/balance`、`/baltop` 每行都会调用的最热路径。采用按余额值的 `ConcurrentHashMap`（读无锁）缓存，真实负载命中近 100%。
  - 单线程展示吞吐 **~37–47×**。
  - **多线程并发**（PlaceholderAPI/记分板是多线程读）：8 线程聚合吞吐 **~150–340×**。附带发现：原 `shown` 因每次都分配大量字符串在并发下被 GC 限制、几乎不随线程扩展；缓存命中路径零分配、线性扩展。
- **`/pay` 等命令金额校验去正则**（`CommandCore.isDouble`）：字母检测改手写 ASCII 扫描、小数位正则提升为 `static final`，消除每次调用编译正则。**~1.8–3.4×**。
- **缓存读路径合并查询**（`DataCon.getPlayerDatai` / `getAccountBalance`）：`containsKey + get` 合并为单次 `get`，省一次哈希查找。**~1.3–1.6×**。

> 诚实边界：不现实的高基数（10 万级去重余额、几乎全 miss）场景下 `shown` 约 0.96×（缓存微小开销）；真实负载（在线玩家 + 排行榜去重 ≪ 4096）命中率近 100%，不受影响。

## 🐛 边界修复

- **`Cache.getDataFromCache` 潜伏 NPE**：按玩家名（或 SEMIONLINE 之外的 String 键）未命中时，`pds.get(null)` 会抛 NPE（`pds` 是 `ConcurrentHashMap`，不允许 null 键）。原代码因调用方先用 `CacheContainsKey` 守卫而从未触发；读路径合并查询优化去掉守卫后会暴露。已修复为未命中返回 `null`。

## 🧪 测试

- 新增 [benchmark/](../../benchmark/) 模块：全面基准套件（DataFormat 全方法、整数/小数模式、访问分布、isDouble 分类、缓存读全 UUID 模式 + 未命中、多线程并发）+ 行为等价正确性套件。
- 全量多模块编译 BUILD SUCCESS。

## 📌 升级建议

- 从 2.27.0 升级：**直接替换 jar 即可**，无需改配置、无需迁移数据。
- 如需关闭展示缓存（理论上不必要）：缓存为内部实现，无开关；行为与原版完全一致，仅更快。

## ⚖️ 红线（刻意未改）

资金写入与 per-UUID 锁、落库失败失效缓存、跨服同步签名前置校验、Redis KV 签名、SQL 相对增量与连接防护 —— **2.27.0 的安全语义全部保留，一字未改**。
